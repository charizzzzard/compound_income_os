# Monthly Portfolio Decision Brief Contract

## Purpose

The Monthly Portfolio Decision Brief consolidates already-existing CIOS evidence
into a compact monthly Human Operator review surface.

It is decision support only. It does not create an order, execute a trade,
automate investment advice, alter scores, alter rankings, alter valuation logic
or change portfolio rules.

## Inputs

The MVP consumes processed, already-produced artifacts only.

Mandatory input:

- `data/processed/personal_monthly_buy_ranking.csv`

Optional review inputs:

- `data/processed/personal_cash_refill_review.csv`
- `data/processed/personal_rebalance_review.csv`
- `data/processed/data_freshness_summary.json`
- `data/processed/decision_quality_state.json`
- `data/processed/decision_review_queue.csv`

Missing optional review inputs must remain visible as `MISSING` or
`NOT_AVAILABLE` evidence. They must not be silently imputed, overwritten,
suppressed or converted into accepted facts.

## Generated Outputs

Default generated outputs are:

- `data/processed/monthly_portfolio_decision_brief.json`
- `data/processed/monthly_portfolio_decision_brief.csv`
- `reports/<as_of_date>/monthly_portfolio_decision_brief.md`

These outputs are generated local artifacts by default and must not be committed
as real personal portfolio decision evidence unless the Human Operator accepts a
separate tracked-artifact boundary.

## Local / Generated Boundary

The producer writes to ignored local generated paths by default. External review
must rely on source code, tests, this contract, central handoff metadata,
schemas, sanitized examples, manifests, hashes, status rows or omitted-artifact
records rather than real private decision outputs.

The producer must not read private raw, broker, provider, credentials, user-agent
or private strategy files directly.

## Mandatory And Optional Input Treatment

The monthly ranking artifact is mandatory because the brief cannot summarize the
monthly decision state without upstream ranking evidence.

If the mandatory ranking artifact is missing, unreadable or schema-invalid,
`decision_brief_status` must be `BLOCKED`.

Optional review artifacts are not allowed to block file generation. Their
missing or unreadable state must remain visible and must usually move the brief
to `REVIEW`.

## Status Semantics

`decision_brief_status` values:

- `READY`: mandatory ranking evidence is available and optional review evidence
  does not indicate review-required state.
- `REVIEW`: mandatory ranking evidence is available, but optional review
  evidence is missing, degraded, stale, unknown, review-required or contains open
  review queue items.
- `BLOCKED`: mandatory ranking evidence is missing, unreadable or invalid.

Input artifact status values:

- `AVAILABLE`: artifact exists and is readable.
- `MISSING`: artifact does not exist.
- `REVIEW`: artifact exists but is unreadable, schema-invalid or redacted.
- `NOT_APPLICABLE`: reserved for future explicit non-selected artifacts.

## Missing / Stale / Unknown Handling

Missing, stale or unknown evidence must remain visible.

The brief must preserve Data Freshness states such as `STALE`, `MISSING`,
`UNKNOWN`, `REVIEW_REQUIRED`, `NOT_AVAILABLE` and `NOT_APPLICABLE` where present
in upstream evidence.

The brief must not infer freshness from file existence, file names, modified
times or unrelated successful stages.

## Operator Acceptance Boundary

The brief is a review surface. It can help the Human Operator inspect whether
monthly evidence is ready, review-required or blocked.

The Human Operator remains final acceptance authority. Acceptance, rejection,
deferral, no-action or manual action must be captured separately where required
by the Decision State Capture contract.

## Privacy And Handoff Treatment

Real generated monthly portfolio decision briefs may contain portfolio context
and must remain local/generated by default.

External review packets may include code, tests, contracts, metadata, schemas,
hashes, manifests, sanitized examples or omitted-artifact records. They must not
include real private holdings, broker/provider files, private raw evidence,
credentials, local absolute paths or private strategy material.

Tracked sanitized example outputs live under
`examples/monthly_portfolio_decision_brief/`. They are reviewer-facing
documentation artifacts only and do not replace real generated local outputs.

## Personal Run Integration

The brief is available as the optional Personal Run stage
`monthly_portfolio_decision_brief`.

The stage reuses the existing brief producer and must not duplicate ranking,
scoring, valuation, portfolio-rule, evidence aggregation or Markdown rendering
logic.

The stage records generated JSON, CSV and Markdown outputs in the Personal Run
artifact index and records the expected monthly ranking, portfolio-health, Data
Freshness, Decision Quality and review-queue inputs in `personal_run_used_inputs`.

Expected missing or degraded evidence is surfaced through the generated brief as
`BLOCKED`, `REVIEW`, `MISSING`, `NOT_AVAILABLE`, `STALE`, `UNKNOWN`,
`REVIEW_REQUIRED` or equivalent visible status. It must not be converted to a
clean `READY` state.

## Future Extension Points

Future patches may add:

- Sanitized example brief outputs.
- Schema-level review artifacts.
- Manifest/hash rows for local generated briefs.
- Ranking robustness and sensitivity evidence once a producer exists.

Each extension must preserve the non-scope boundaries below.

## Explicit Non-Scope

This contract does not implement or approve:

- broker import staging;
- broker API;
- order execution;
- buy/sell automation;
- investment advice;
- valuation automation;
- DCF;
- provider/API integration;
- replay;
- backtesting;
- simulation;
- outcome attribution;
- tax logic;
- scoring formula changes;
- ranking formula changes;
- portfolio-rule changes;
- dashboard UI/server;
- runtime enforcement;
- production readiness;
- investment readiness;
- legal, tax or commercial approval.
