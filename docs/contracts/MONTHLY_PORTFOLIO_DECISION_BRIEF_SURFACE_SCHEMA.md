# Monthly Portfolio Decision Brief Surface Schema

## Purpose

This document defines the reviewer-facing JSON, CSV and Markdown surface for the
Monthly Portfolio Decision Brief.

It is schema-level documentation for review and test hardening. It is not runtime
enforcement, not a trading rule, not investment advice and not production or
investment readiness.

## JSON Surface

Monthly Brief JSON examples must expose these top-level keys:

- `as_of_date`
- `data_freshness_summary`
- `decision_brief_status`
- `decision_quality_summary`
- `generated_at_utc`
- `input_artifact_status`
- `non_claims`
- `operator_acceptance_boundary`
- `operator_checklist`
- `portfolio_decision_readiness`
- `portfolio_health_summary`
- `ranking_summary`
- `review_queue_summary`
- `schema_version`
- `source_module`

The JSON surface must preserve visible status fields instead of silently
normalizing missing or degraded evidence. Decision Quality confidence is process
confidence only and must not be presented as investment confidence.

## CSV Surface

Monthly Brief CSV examples must use these columns, in this order:

- `section`
- `item`
- `status`
- `value`
- `source_artifact`
- `notes`

The CSV surface is a reviewer-facing status row surface. It must not expose real
portfolio values, broker data, provider files, credentials, local absolute paths
or private strategy material.

## Markdown Surface

Monthly Brief Markdown examples must include:

- a synthetic/sanitized example disclaimer;
- visible `decision_brief_status`;
- visible evidence gaps for `REVIEW` examples;
- explicit non-claims;
- the Human Operator acceptance boundary.

Markdown examples must remain review support only. They must not instruct the
operator to buy, sell, place orders or execute trades.

## Status Values

Reviewer-facing examples and tests may use these status values where applicable:

- `READY`
- `REVIEW`
- `BLOCKED`
- `AVAILABLE`
- `MISSING`
- `NOT_AVAILABLE`
- `NOT_APPLICABLE`
- `STALE`
- `UNKNOWN`
- `REVIEW_REQUIRED`

`READY`, `REVIEW` and `BLOCKED` describe the brief-level decision surface.
`AVAILABLE`, `MISSING`, `NOT_AVAILABLE`, `NOT_APPLICABLE`, `STALE`, `UNKNOWN`
and `REVIEW_REQUIRED` describe artifact or upstream evidence state.

## Sanitized Example Boundary

Tracked examples under `examples/monthly_portfolio_decision_brief/` are
synthetic and sanitized reviewer-facing documentation artifacts only.

Real generated outputs remain local/generated by default:

- `data/processed/monthly_portfolio_decision_brief.json`
- `data/processed/monthly_portfolio_decision_brief.csv`
- `reports/<as_of_date>/monthly_portfolio_decision_brief.md`

The surface must not include private/raw/broker/provider/credential/local
absolute path data. It must not claim production readiness, investment readiness,
broker/API integration, buy/sell automation or order execution.

The Human Operator remains final acceptance authority.
